# Независимое C++-ядро

Это автономный C++-контур для поэтапного переноса расчётной части цифрового
двойника из TypeScript. SUMO не требуется.

## Уже перенесено

- продольная физика вагона: ограничение силы и мощности тяги;
- плавное изменение ускорения с ограничением рывка;
- служебное и экстренное торможение;
- сопротивление движению, уклон и расход вспомогательных систем;
- механическая энергия торможения, рекуперация и непринятая сетью энергия;
- баланс тяги и рекуперации по электрическим секциям;
- локальное распределение принятой энергии между тормозящими вагонами;
- сетевые и секционные пики мощности, накопленная энергия подстанций;
- энергетически оптимальная диспетчеризация разгона с учётом доступной
  рекуперации и загрузки питающей подстанции;
- контроллер приоритета перекрёстка для обоих направлений;
- удержание трамвайного разрешения до полного освобождения переезда;
- ориентированный граф рельсовых сегментов с полилинейной геометрией;
- продвижение вагона через границы сегментов;
- выбор прямого или отклонённого направления стрелки отдельно для каждого
  маршрута;
- физический безопасный интервал и запрет обгона, включая границы сегментов;
- плавное торможение к точной координате платформы без её проезда;
- блокировка открытия дверей до полной остановки;
- настраиваемое время стоянки и автоматическое закрытие дверей;
- режим пропуска остановки для непассажирского рейса;
- четыре независимых плана движения: маршрут 2 в обе стороны и два направления
  маршрута 21;
- плановое время выпуска каждого вагона;
- интервальное регулирование только внутри своей маршрутной группы;
- ускоренное восстановление интервала после задержки и замедление при
  сближении;
- скользящий средний фактический интервал по отправлениям с остановки;
- конечный автомат депо: ожидание, выпуск, выход на линию, пассажирская работа,
  снятие и возврат;
- отложенное снятие только после обслуживания последней пассажирской остановки;
- маршрутный указатель «TO LINE» / «TO DEPOT via …» и запрет посадки в
  непассажирском режиме;
- подъездной путь, деповская стрелка и статистика вагонов в депо и на линии;
- автономный C++ runner для headless-проверок;
- стабильный браузерный C ABI версии 11 для четырёх направлений, 20 вагонов и
  16 тяговых секций;
- независимый `LiveSimulationCore`, который не зависит от React и Canvas;
- настоящий freestanding C++ WebAssembly-модуль без WASI и JS-физики;
- компактная тестовая сеть 2+21 внутри freestanding WebAssembly-модуля.

## Важно: состояние переноса

Основной веб-симулятор использует `SimulationEngine` как оркестратор. Физика
вагона, автоматы остановок, светофоров, стрелок и депо, а также баланс тяговых
секций и решения энергетического диспетчера выполняются в `tram-core.wasm`.
TypeScript сопоставляет конфигурационные идентификаторы с индексами C ABI,
передаёт состояние и визуализирует возвращённые C++ результаты.

В TypeScript пока остаются граф маршрутов и продвижение по нему, пассажирская
модель, расписание и формирование диспетчерских команд. Поэтому перенос
инженерного ядра уже является рабочим, но перенос всей операционной логики ещё
не завершён.

Координаты линий, подписи, элементы управления и Canvas и после завершения
переноса останутся в TypeScript как слой данных и визуализации; расчётное
состояние должно будет поступать из WebAssembly через адаптер.

## macOS

Понадобятся только стандартные инструменты разработчика Apple:

```bash
xcode-select --install
```

Проверка C++-ядра:

```bash
cd cpp-core
make test
```

Веб-интерфейс сразу открывает действующую сеть маршрутов 2+21 на текущем
TypeScript-ядре; отдельной C++-лаборатории в интерфейсе нет.

## WebAssembly

Готовый компактный модуль находится в `public/wasm/tram-core.wasm`. Он собран
из `src/wasm_live_core.cpp`, не имеет импортов и запускается прямо через
`WebAssembly.instantiate`.

Для воспроизводимой пересборки без системной установки Emscripten:

```bash
npm install --no-save --package-lock=false browsercc
node cpp-core/scripts/compile-portable-wasm.mjs
```

Полный вариант со стандартной библиотекой можно собрать после активации
Emscripten SDK:

```bash
cpp-core/scripts/build-wasm.sh
```

Команда создаст `public/wasm/tram-core.mjs` и `tram-core.wasm`. Публичная
граница описана в `include/tram/core_c_api.h`, браузерный адаптер — в
Обычная C++-сборка и тест ABI не требуют Emscripten.

## CMake

Альтернативная сборка:

```bash
cmake -S cpp-core -B cpp-core/build-cmake
cmake --build cpp-core/build-cmake
ctest --test-dir cpp-core/build-cmake --output-on-failure
./cpp-core/build-cmake/native_runner replay.json
```

## Граница модулей

- `vehicle_dynamics.*` — физика и энергетика одного вагона;
- `priority_controller.*` — конечный автомат перекрёстка;
- `track_graph.*` — геометрия путей, стрелки, маршрутизация и запрет обгона;
- `stop_controller.*` — остановка у платформы, двери и время стоянки;
- `service_controller.*` — расписание, маршрутные группы и интервалы;
- `depot_controller.*` — суточный выпуск, снятие, режим обслуживания и
  маршрутный указатель;
- `native_runner.cpp` — автономный сценарий и экспорт кадров;
- `simulation_core.*` — живой фиксированный шаг независимого ядра;
- `core_c_api.*` — стабильная C-граница для native и WebAssembly;
- `wasm_live_core.cpp` — freestanding реализация ABI для браузера;
- `src/App.tsx` — единственный интерфейс карты и панели управления.

Автономные C++-расчёты не зависят от React и Canvas. Основной интерфейс на
каждом фиксированном шаге вызывает stateful C++ WebAssembly authority для всех
вагонов: физики, сил, энергии, рекуперации, интервалов, безопасного перемещения,
фаз светофоров и состояний остановки/дверей. TypeScript хранит городскую
геометрию сценария, накладывает разрешённую C++ дистанцию на сегменты карты и
формирует UI-снимки.
