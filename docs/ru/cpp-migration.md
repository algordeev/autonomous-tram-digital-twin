# План переноса цифрового двойника на C++

## Архитектура

```text
React + Canvas (TypeScript)
  карта · сценарий · команды · снимки
                 ↕ ABI 12
       C++ WebAssembly authority
 physics · energy · headway · movement cap
     signals · stop/dwell state machine
```

Для автономных тестов C++ также собирается как обычная консольная программа.

Браузер обращается к C++-ядру на каждом фиксированном шаге. TypeScript больше
не интегрирует физику вагона и не меняет фазы светофоров в рабочем браузерном
режиме. Он передаёт C++ наблюдения от геометрии сети и отображает возвращённое
состояние. Резервная TypeScript-реализация сохраняется только для headless-
тестов и случая, когда WebAssembly не удалось загрузить.

## Этапы

1. **Готово:** физика вагона, энергетика и приоритет перекрёстка.
2. **Готово:** граф путей, продвижение по сегментам, стрелки и физический
   запрет обгона.
3. **Готово:** остановки, двери и время стоянки.
4. **Готово:** расписание четырёх направлений и интервальное регулирование.
5. **Готово:** депо, подъездной путь, выпуск и снятие вагонов с линии.
6. **Готово:** C ABI зафиксирован, настоящий freestanding C++ WASM собран.
7. **Готово:** live-core ABI 12 обслуживает сеть 2+21: четыре направления,
   несколько вагонов, интервалы внутри своей группы, конфликтные зоны,
   остановки, ручной режим, состояние депо и энергетику.
8. **Готово для интерфейса:** отдельные лаборатории, демонстрационные
   перекрёстки и replay-режимы удалены. Пользователь работает только с
   существующим симулятором маршрутов 2+21.
9. **Готово:** stateful C++ authority подключён к основному fixed-step циклу.
   Он владеет скоростью, ускорением, силами, всеми накопителями энергии,
   интервальным коэффициентом, ограничением безопасного перемещения, фазами
   светофоров и таймерами остановок/дверей.

## Что намеренно остаётся в TypeScript

- неизменяемое описание городской геометрии и привязка результата движения к
  сегментам карты;
- React/Canvas, подписи, панели и обработка пользовательских событий;
- построение ETA и текстового журнала из снимков состояния;
- таблица суточного выпуска как конфигурация сценария и визуальная модель
  автомобилей.

Это адаптер среды и представление, а не альтернативная браузерная физика.

## Правило миграции

Каждый модуль сначала получает одинаковые входные данные в TypeScript и C++.
Переход считается завершённым только после совпадения результатов в
детерминированных тестах. Это защищает текущие сценарии маршрутов 2 и 21 от
регрессий во время постепенного переноса.
